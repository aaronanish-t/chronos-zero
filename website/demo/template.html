Safety kernel for AI agents

Your agent's next action, proven safe before it touches production.

Chronos-Zero sits between an AI agent and the systems it changes. Every tool call runs first in a throwaway copy of your database, the result is checked by the Z3 theorem prover against your rules, and only a proven-safe change is committed. A rejected change is rolled back and the agent is told exactly which rule it broke, so it can fix the call itself.

The problem

Guardrails read what an agent says. The damage is in what it does.

LLM guardrails and text filters

Classify the prompt or the tool call as text. A harmful database write can look perfectly polite. The answer is a probability, and it takes another model call to get it: roughly 1.2 to 2 seconds.

Chronos-Zero

Executes the call for real inside a PostgreSQL transaction that is never committed, reads the state it would leave behind, and asks Z3 for a proof that your invariants still hold. The answer is SAT or UNSAT, with the broken rule and the exact values that broke it.

How it works

One tool call, five steps, a few milliseconds.

1

Intercept

The agent's tool call reaches the kernel instead of production.

POST /v1/kernel/execute
2

Fork

A dedicated connection opens a transaction and a named SAVEPOINT: a private copy of the data.

SAVEPOINT cow_branch_…
3

Simulate

The action runs for real inside that copy. The kernel reads the state before and after.

state_pre → state_post
4

Prove

Z3 binds those exact values and checks every rule as a tracked assertion, with a 50 ms ceiling.

SAT / UNSAT + unsat core
5

Commit or heal

SAT: write a SHA-256 receipt, then COMMIT. UNSAT: ROLLBACK and hand the agent the broken rule so it retries correctly.

1-turn self-healing

Don't trust us

Every verdict ships with something you can check.

The proof is the exact formula Z3 solved, and the receipt is its SHA-256. You can recompute both without running any of our code.

Recompute the receipt

Run a scenario above and press "Verify receipt". Your browser hashes the SMT-LIB2 itself and compares it with the receipt the verifier issued.

sha256(smt2_dump) == sha256_proof_hash

Re-run the proof in stock Z3

Save the SMT-LIB2 from a verdict, then assume every rule. The result reproduces the verdict: unsat for a blocked action, sat for a committed one.

(check-sat-assuming (INV_FIN_01_ESCROW_CAP
                     INV_FIN_02_SLA_ATTESTATION))

Audit the chain

Each verdict is appended to a SHA-256 hash chain in a separate, append-only database before anything commits. The product UI recomputes every link and the Merkle root in the browser.

entry = sha256(prev | trace | smt2 | status | ts)

Domain cartridges

Rules for where mistakes are expensive.

A cartridge is a set of invariants plus the state readers for one domain. Teams add their own rules in plain English; Chronos compiles them to tracked Z3 assertions and tests each one against a passing and a failing example before it goes live.

Healthcare

Clinical agents that prescribe and file claims.

INV_MED_01 eGFR < 30 ⇒ metformin dose = 0
INV_MED_02 claim ⇒ ≥ 6 weeks documented therapy
INV_MED_03 daily dose ≤ 2000 mg

Fintech

Treasury and payout agents that move money.

INV_FIN_01 spent + transfer ≤ daily limit
INV_FIN_02 transfer ⇒ allowlisted IBAN and SLA ≤ 200 ms

Cloud DevOps

SRE agents with database and network access.

INV_OPS_01 row count after ≥ row count before
INV_OPS_02 never port 22 open to 0.0.0.0/0
